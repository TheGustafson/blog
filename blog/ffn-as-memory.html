The Feed-Forward Block as Key-Value Memory

15 min readbuilds on Self-Attention: Q, K, V from First Principles and Vectors, Matrices, and the Spaces They Live In

A note on this series

I built this series as a learning project and used Claude extensively for research, drafting, critique, coding, and revision. I chose the curriculum and dependency order, drove the questions, edited the explanations, developed the interactive examples, and take responsibility for the published result.

This is an educational first edition rather than a formal reference. I am reviewing the articles against primary sources, testing the executable examples, and tracking corrections as the series matures. Some examples require specific hardware, model weights, or external services; they are teaching examples, not a tested deployment recipe.

Rows of W_1 act as keys that match input patterns; columns of W_2 are the values those keys retrieve.

Attention lets token positions exchange information. The feed-forward network that follows it processes each position independently, using the same learned weights at every position.

In the original transformer, the FFN is two matrix multiplications with a ReLU between them.

At the original 4× expansion ratio, the FFN contains two-thirds of an encoder layer’s main projection weights. Geva et al. (2021) interpret those weights as keys and values: match an input pattern, then add its associated output direction.

Prerequisites

You'll want to be comfortable with the self-attention mechanism from Post 4.1, including the residual stream picture introduced there: every block reads from a shared per-token vector and adds its result back. The FFN is one of those blocks. I'll compare its key-value lookup to attention's key-value lookup throughout. Familiarity with matrix multiplication at the level of Post 1.2 is enough for the math here.

The basic FFN

The standard feed-forward block in a transformer is:

FFN(x)=W2⋅act(W1⋅x+b1)+b2\text{FFN}(x) = W_2 \cdot \text{act}(W_1 \cdot x + b_1) + b_2FFN(x)=W2​⋅act(W1​⋅x+b1​)+b2​

where xxx is the residual stream vector at a single position, W1W_1W1​ has shape (dff,dmodel)(d_{ff}, d_{model})(dff​,dmodel​), and W2W_2W2​ has shape (dmodel,dff)(d_{model}, d_{ff})(dmodel​,dff​). In the original "Attention Is All You Need" paper, the activation function was ReLU.

The key dimension here is dffd_{ff}dff​. It's typically 4 times dmodeld_{model}dmodel​. So if your model has a hidden dimension of 4096, the intermediate representation expands to 16,384 dimensions, then gets projected right back down to 4096. The nonlinearity acts between the expansion and contraction.

A wider intermediate layer supplies more learned projections of the input and more activation coefficients for the output to combine. The nonlinearity lets these coefficients change differently with the input; without it, the two matrices would compose into one linear map.

There's no interaction between token positions here. Each position gets the exact same linear transformations applied independently. Attention handles the cross-position communication; the FFN handles per-position computation.

The parameter budget

The FFN block:

  • W2W_2W2​: 16384×4096=67M16384 \times 4096 = 67M16384×4096=67M parameters
  • Total: 134M parameters (ignoring biases)

The attention block (with 4 projection matrices WQ,WK,WV,WOW_Q, W_K, W_V, W_OWQ​,WK​,WV​,WO​):

  • Each is 4096×4096=16.8M4096 \times 4096 = 16.8M4096×4096=16.8M parameters
  • Total: 67M parameters

The FFN has twice the projection parameters of standard multi-head attention in this example. Across 32 layers that is over 4 billion FFN parameters. Parameter share is not a measurement of where a corresponding share of knowledge is stored.

The key-value memory interpretation

First, W1⋅xW_1 \cdot xW1​⋅x computes a dot product between each row of W1W_1W1​ and the input xxx. A dot product is a similarity measure. So each row of W1W_1W1​ is a pattern (a "key"), and the dot product measures how well the current input matches that pattern. The iii-th element of the intermediate vector is just: how much does xxx look like the iii-th row of W1W_1W1​?

Then ReLU zeros out all the negative values. This is a hard gate. Only the keys that match strongly enough (positive dot product after bias) survive.

Finally, W2W_2W2​ multiplies this sparse activation vector. You can think of this column by column. Each column of W2W_2W2​ is a value associated with one intermediate neuron. When neuron iii fires with activation aia_iai​, the output gets ai⋅W2[:,i]a_i \cdot W_2[:, i]ai​⋅W2​[:,i] added to it. The stronger the match, the more that value contributes.

Put it all together:

FFN(x)=∑i=1dffact(ki⋅x+bi)⋅vi+b2\text{FFN}(x) = \sum_{i=1}^{d_{ff}} \text{act}(k_i \cdot x + b_i) \cdot v_i + b_2FFN(x)=i=1∑dff​​act(ki​⋅x+bi​)⋅vi​+b2​

where kik_iki​ is the iii-th row of W1W_1W1​ (the key) and viv_ivi​ is the iii-th column of W2W_2W2​ (the value).

That's a key-value memory. The input is the query, the first matrix stores keys, the activation function decides which keys matched, and the second matrix stores the values that get retrieved. With dff=16384d_{ff} = 16384dff​=16384, each layer has 16,384 memory slots.

This is structurally similar to attention, which is also a key-value lookup. But the two kinds of key-value lookup serve totally different purposes:

  • Attention keys and values come from the current sequence. They're dynamic, computed on the fly from other tokens in the context window. Different input, different keys and values.
  • FFN keys and values are baked into the weight matrices during training. They're fixed. The same 16,384 memory slots exist regardless of what the input is. What changes is which ones get activated.

Attention also has persistent learned projection weights. The comparison here is specifically between its input-dependent K/V activations and the FFN’s fixed key/value matrices.

ReLU has an exact zero region, but its positive outputs are continuous, not binary. SwiGLU multiplies two input-dependent projections and can produce signed values. The toy view keeps the same width to compare the operations; it therefore gives SwiGLU an extra matrix.

Also notice the expand-contract shape. Four input dimensions blow up to eight intermediate neurons and then collapse back to four output dimensions. Common matched-budget examples use 4x (or about 2.7x for SwiGLU), giving the network thousands of intermediate "memory slots" per layer.

SwiGLU: the modern FFN

Llama and Mistral use SwiGLU, a gated alternative to the original ReLU FFN. Other models use different gates; Gemma, for example, uses a GELU-based gated FFN.

Shazeer's 2020 GLU study compared gated variants under a matched parameter and compute budget and found improvements on its tested language tasks.

FFNSwiGLU(x)=W2(Swish(W1x)⊙(Wgatex))\text{FFN}_{SwiGLU}(x) = W_2(\text{Swish}(W_1 x) \odot (W_{gate} x))FFNSwiGLU​(x)=W2​(Swish(W1​x)⊙(Wgate​x))

Instead of two weight matrices, there are now three: W1W_1W1​, WgateW_{gate}Wgate​, and W2W_2W2​. The Swish activation (x⋅σ(x)x \cdot \sigma(x)x⋅σ(x), where σ\sigmaσ is the sigmoid) replaces ReLU, and the WgateW_{gate}Wgate​ projection provides a multiplicative gate. The element-wise product ⊙\odot⊙ lets one input-dependent projection modulate another. Both factors can be negative, so this is not a Boolean agreement test.

Each intermediate feature now depends on two learned projections. The memory analogy still helps, but the coefficient is a signed product rather than a positive match score.

To keep the total parameter count comparable, models using SwiGLU reduce dffd_{ff}dff​. Three matrices instead of two means you need to shrink each one. The standard ratio drops from 4×dmodel4 \times d_{model}4×dmodel​ to about 83×dmodel\frac{8}{3} \times d_{model}38​×dmodel​ (often rounded to a multiple of 256 for hardware alignment). For LLaMA 2 with dmodel=4096d_{model} = 4096dmodel​=4096, the actual dffd_{ff}dff​ is 11008. Not a round number, but hardware-aligned.

SiLU and Swish name the same activation used in SwiGLU. A model card mentioning SiLU alone does not establish the full gated architecture; check the projections too.

Attention vs FFN: the division of labor

Attention moves information between positions. It's how the model at position 10 can "see" what's at position 3. It reads from the residual stream at every position and writes a weighted combination back. It's a communication channel.

The FFN transforms information at each position independently. It reads the residual stream at position 10 and writes back to position 10. No other position is involved. It's a computation step, or if you buy the key-value memory framing, a memory recall step.

Elhage et al. describe both blocks as reading from and writing to the residual stream. Both contain learned weights and can participate in factual predictions.

For an illustrative prediction of “Paris” after “The capital of France is,” attention can bring information about “capital” and “France” to the final position. An FFN update there can then increase the output score for “Paris.” This describes one possible contribution, rather than a complete account of a trained model’s prediction.

Each layer receives representations changed by the layers before it. Identically shaped FFNs can therefore learn different functions at different depths.

The FFN output is added to the residual stream, not substituted into it. The full computation at each layer is:

h=x+Attn(Norm(x)),xnext=h+FFN(Norm(h))h = x + \text{Attn}(\text{Norm}(x)), \qquad x_{next} = h + \text{FFN}(\text{Norm}(h))h=x+Attn(Norm(x)),xnext​=h+FFN(Norm(h))

The residual path carries the previous vector forward while the FFN adds its update. That update can reinforce or cancel existing features. In the memory interpretation, it is a sum of retrieved value vectors.

Knowledge neurons: finding facts in the weights

Does the key-value interpretation help explain factual predictions in a trained model?

Dai et al. (2022) tested this interpretation with interventions in pretrained BERT models.

They used an integrated-gradients-based attribution method, then refined neurons across prompts expressing the same fact. Suppressing or amplifying selected activations changed the probability of the associated completion. This is not simply selecting whichever neurons have the largest activations.

The selected coordinates participate in those predictions, but need not store independent, readable facts or work for every paraphrase.

ROME and MEMIT modify MLP output weight matrices to change selected factual associations. ROME uses a rank-one matrix update, which can change many entries rather than one neuron or column. Such edits can also have unwanted effects on other prompts.

A model with 32 FFN layers and dff=16384d_{ff}=16384dff​=16384 has 524,288 intermediate coordinates. Those coordinates are not a count of stored facts: features can be distributed across neurons, and one neuron can participate in multiple features. The memory interpretation is a decomposition of the computation, not a literal database schema.

Worked example

Let's trace a concrete input through a small FFN with dmodel=4d_{model} = 4dmodel​=4 and dff=8d_{ff} = 8dff​=8. I'm using the same numbers as the visualization above, so you can follow along by clicking the neurons.

Input vector: x=[0.80,0.30,−0.50,0.60]x = [0.80, 0.30, -0.50, 0.60]x=[0.80,0.30,−0.50,0.60]

Step 1: Key matching (W1⋅x+b1W_1 \cdot x + b_1W1​⋅x+b1​)

Each of the 8 rows of W1W_1W1​ computes a dot product with xxx. Take neuron 0 as an example. Its key (row 0 of W1W_1W1​) is [0.60,0.20,−0.30,0.10][0.60, 0.20, -0.30, 0.10][0.60,0.20,−0.30,0.10]. The dot product is:

0.60×0.80+0.20×0.30+(−0.30)×(−0.50)+0.10×0.60=0.48+0.06+0.15+0.06=0.750.60 \times 0.80 + 0.20 \times 0.30 + (-0.30) \times (-0.50) + 0.10 \times 0.60 = 0.48 + 0.06 + 0.15 + 0.06 = 0.750.60×0.80+0.20×0.30+(−0.30)×(−0.50)+0.10×0.60=0.48+0.06+0.15+0.06=0.75

After adding the bias (b1[0]=0.10b_1[0] = 0.10b1​[0]=0.10), neuron 0 has a pre-activation of 0.850.850.85. That's a strong match. This key pattern wanted a positive value in dimension 0 and a negative value in dimension 2, and the input delivered.

Now do the same for all 8 neurons. Some will get large positive pre-activations (strong match), some near zero, some negative (no match).

Step 2: Activation (ReLU)

ReLU zeros out all negative values. This is where the "gating" happens. Only the neurons whose keys actually matched the input get to contribute. In the visualization, those are the warm-colored circles. The gray ones had negative pre-activations and got clamped to zero. Their contribution is zero for this input.

ReLU can produce exact zeros, so only a subset of value vectors contributes for a given input. The active fraction depends on the model, layer, and input; the toy example below deliberately uses sparse activations.

Step 3: Value retrieval (W2⋅activatedW_2 \cdot \text{activated}W2​⋅activated)

Each surviving neuron contributes its corresponding column from W2W_2W2​ to the output, scaled by how strongly it activated. If neuron 0 activated at 0.850.850.85 and its value vector (column 0 of W2W_2W2​) is [0.30,−0.10,0.40,0.20][0.30, -0.10, 0.40, 0.20][0.30,−0.10,0.40,0.20], it adds 0.85×[0.30,−0.10,0.40,0.20]=[0.26,−0.09,0.34,0.17]0.85 \times [0.30, -0.10, 0.40, 0.20] = [0.26, -0.09, 0.34, 0.17]0.85×[0.30,−0.10,0.40,0.20]=[0.26,−0.09,0.34,0.17] to the output. The final output is the sum of all these weighted value vectors plus the output bias.

You can think of each intermediate neuron as a conditional rule: "If the input looks like this key pattern, add this value vector to the output." Training doesn't explicitly program these rules. Training adjusts the key and value matrices through gradient updates. But the structure of the computation is a pattern-matching lookup. Geva et al. showed that you can even decode the value vectors through the unembedding matrix to see which output tokens each neuron "wants to promote." Many neurons have interpretable specializations: some activate for number words, others for geographic terms, others for specific syntactic patterns.

Toggle between ReLU and SwiGLU above to compare the coefficients applied to the value columns. SwiGLU multiplies two projections element by element, after applying SiLU to one. Both magnitude and sign affect each column's contribution.

Common misconceptions

"The FFN is just a nonlinearity between attention layers." In the standard dff=4dmodeld_{ff}=4d_{model}dff​=4dmodel​ block, its two projections contain twice as many weights as the four attention projections. Interventions show that FFN computation can affect factual predictions, though it also serves many other functions.

"Only FFNs store knowledge." FFNs have a useful memory interpretation, and interventions have localized some factual associations there. Attention's projection weights are learned parameters too. Dynamic attention weights should not be confused with the persistent parameters that compute them; the division into routing and memory is a working model, not an exclusive allocation of knowledge.

"Bigger dffd_{ff}dff​ always helps." Widening the FFN adds parameters and arithmetic. Whether that improves quality at a fixed training budget depends on the rest of the architecture, data, and optimization; the memory analogy cannot answer it.

"The FFN mixes information across the sequence." A batched FFN applies the same weights independently to each position. Processing positions in parallel does not mix their information.

Additional reading (and watching)

  • Vaswani, A., et al. (2017). Attention Is All You Need. NeurIPS 2017. The original transformer paper; introduces the FFN as a position-wise two-layer network with ReLU.
  • Geva, M., et al. (2021). Transformer Feed-Forward Layers Are Key-Value Memories. EMNLP 2021. The paper that crystallized the key-value memory interpretation of FFN weights.
  • Shazeer, N. (2020). GLU Variants Improve Transformer. The compact note that introduced SwiGLU and the gated FFN family that took over modern transformers.
  • Dai, D., et al. (2022). Knowledge Neurons in Pretrained Transformers. ACL 2022. Localizes specific factual associations to small sets of FFN neurons.
  • Elhage, N., et al. (2021). A Mathematical Framework for Transformer Circuits. Anthropic. Frames attention and FFN as cooperating reads/writes against a shared residual stream.
  • Meng, K., et al. (2022). Locating and Editing Factual Associations in GPT. NeurIPS 2022. ROME: applies a rank-one update to an MLP output matrix to change a factual association.
  • Meng, K., et al. (2023). Mass-Editing Memory in a Transformer. ICLR 2023. MEMIT: scales the ROME idea to thousands of edits in a single pass.
  • Sukhbaatar, S., et al. (2019). Augmenting Self-attention with Persistent Memory. NeurIPS 2019. Independently formalizes the FFN as a layer of persistent key-value pairs.
