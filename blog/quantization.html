A note on this series

I built this series as a learning project and used Claude extensively for research, drafting, critique, coding, and revision. I chose the curriculum and dependency order, drove the questions, edited the explanations, developed the interactive examples, and take responsibility for the published result.

This is an educational first edition rather than a formal reference. I am reviewing the articles against primary sources, testing the executable examples, and tracking corrections as the series matures. Some examples require specific hardware, model weights, or external services; they are teaching examples, not a tested deployment recipe.

Raw storage for 70 billion weights

70 × 10⁹ × 16/8 bytes = 140 GB

Common scale: 0–140 decimal GB. Payload only; metadata, mixed-precision tensors, runtime buffers, and KV cache add memory. A bit count alone does not specify a quantizer or its quality.

A 70-billion-parameter model needs roughly 140 GB just for raw 16-bit weights. Four-bit storage reduces that payload to 35 GB. The practical questions are what else the format stores, how much the approximation changes the model, and whether the runtime can use it efficiently.

Quantization replaces values with a smaller set of representable values. Uniform integer grids are a useful starting point, though floating-point formats and nonuniform codebooks make different choices.

At four bits, this symmetric construction uses codes −7 through 7: fifteen levels, with one of the sixteen possible bit patterns unused. Other schemes use an asymmetric range and a zero point. An all-zero group needs special handling so that its scale is not used as a zero divisor.

Without clipping, rounding to a uniform grid introduces at most half a grid step of absolute error. That bound says little about the downstream model: different weights have different effects, and errors accumulate through many layers.

Outliers can spend the available range

If most values are near zero but a few are much larger, a single scale must cover those extremes. Small values then share relatively coarse grid steps. Using separate scales for groups can reduce this problem, at the cost of storing more scales and handling more groups.

Outliers in activations and outliers in weights are related but distinct problems. LLM.int8() uses a mixed-precision decomposition for activation outlier dimensions. Keeping selected values at high precision can help, but it also complicates execution. A format needs a kernel that supports its layout efficiently.

GPTQ protects layer outputs

Rounding weights independently minimizes a local weight error. GPTQ instead uses calibration activations to approximate how a layer's output changes. For a weight row and calibration matrix XXX, the reconstruction objective has the form

∥(w−w^)X∥22.\left\|(w-\hat w)X\right\|_2^2.∥(w−w^)X∥22​.

Correlations in XXTXX^TXXT matter: changing another unquantized weight can compensate for some output error from a weight just rounded. GPTQ uses damped second-order information to choose these updates efficiently.

Minimizing this layer-output objective can increase ordinary weight RMSE: the calibration activations determine which errors matter most.

AWQ rescales important channels

AWQ uses activation statistics to identify weight channels worth protecting. It scales selected weight channels up before quantization and compensates by scaling the corresponding input activations down. For a diagonal scale matrix SSS,

WX=(WS)(S−1X).WX=(WS)(S^{-1}X).WX=(WS)(S−1X).

Before quantization, these are the same product. Quantizing the rescaled weights changes which errors the integer grid introduces. AWQ searches for useful scales while retaining a low-bit weight representation; it does not simply store its important weights in FP16.

SmoothQuant addresses activation outliers by moving difficulty from activations into weights through an equivalent rescaling, with a different objective.

Bit width is not a quality score

Four bits means sixteen possible bit patterns, not half the accuracy of eight bits. To evaluate a quantized checkpoint, compare the same base model, tokenizer, prompts, context lengths, and evaluation protocol. Measure the tasks that matter to the application, including long-context or structured-output behavior when relevant.

Perplexities from different datasets or tokenizers cannot establish a universal ranking of quantization methods. A small average change can also hide a larger change on a particular task.

Storage savings and execution speed

A W4A16 kernel stores weights at four bits while consuming 16-bit activations. It may unpack and dequantize weights into a floating-point computation; it is not necessarily an integer matrix multiply. W8A8 and floating-point low-precision kernels have different hardware paths.

Reducing weight traffic can help a bandwidth-limited decode step. It does not imply a fourfold end-to-end speedup: dequantization, kernel efficiency, batching, attention, KV traffic, and host overhead still contribute. A representation that saves memory can even run slower on an unsupported or poorly matched backend.

The KV cache has its own dtype and scaling scheme. Quantizing weights alone does not reduce KV payload, and a runtime's dtype setting does not automatically produce a valid quantized checkpoint.

GGUF describes more than a bit count

GGUF is a container used by llama.cpp and related tools. The tensors inside can use different quantization layouts. Block metadata means a nominal four-bit scheme occupies more than four bits per weight.

For example, Q4_0 stores 32 weights in 18 bytes, including its scale: 4.5 bits per weight. Q4_K also averages 4.5 bits per weight within its 256-weight superblock, using a different arrangement of scale information. Equal storage density does not make the two quantizers equivalent.

Try the rounding rule

The NumPy codes above are stored as eight-bit integers for convenience; this teaching example does not pack two four-bit codes into one byte. Real formats must specify that packing and their metadata.

When one device still cannot meet the memory or latency requirement, the next option is parallelism across devices.
