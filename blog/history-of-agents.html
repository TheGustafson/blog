Arc 10: Tools, Protocols & Agent Loops

A Short History of Agents: From ReAct to 2026

11 min readbuilds on Special Tokens, Chat Templates, and Input Formatting, Tool-Use Fine-Tuning and Context Engineering: Compaction, Clearing, and Memory

A note on this series

I built this series as a learning project and used Claude extensively for research, drafting, critique, coding, and revision. I chose the curriculum and dependency order, drove the questions, edited the explanations, developed the interactive examples, and take responsibility for the published result.

This is an educational first edition rather than a formal reference. I am reviewing the articles against primary sources, testing the executable examples, and tracking corrections as the series matures. Some examples require specific hardware, model weights, or external services; they are teaching examples, not a tested deployment recipe.

A useful thread through recent LLM-agent work is the repeated cycle of generating an action, executing it, and returning an observation. ReAct made that cycle easy to inspect in a transcript; tool training, structured APIs, and MCP changed how its parts connect.

The question through this history is what each proposal changed: the model’s training, the action format, the available tools, or the context carried into another turn.

The problem this layer solves

A language model can describe how to run a test suite. To run it and inspect the result, an application must execute the command and return the output to the model.

Here, an LLM agent means a system that repeatedly generates actions, executes them, and supplies the resulting observations to the next generation. It stops when the task is complete or the runtime ends the run.

Prerequisites

This post sits near the end of the series. To follow the trajectory, it helps to already have a feel for a few earlier layers:

  • What a tokenizer does and why chat templates matter (Special Tokens, Chat Templates, and Input Formatting). Agent protocols live inside the transcript format.
  • The difference between training a behavior into a model (Tool-Use Fine-Tuning) and prompting it at inference time. Most of the history here is a swing between the two.
  • The distinction between model output and application execution. The next post develops function calling in detail; this history introduces why that interface appeared.

The minimal formalism

We can compare the systems in this history using a loop with four parts:

  • A model π\piπ that produces tokens.
  • An action space A\mathcal{A}A — the set of things the model is allowed to ask the world to do.
  • A tool (or environment) τ\tauτ that executes an action and returns an observation.
  • An observation ooo that gets pasted back into the context for the next model step.

One step of the loop is just:

at∼π(⋅∣ct),ot=τ(at),ct+1=ct⊕at⊕ota_t \sim \pi(\cdot \mid c_t), \quad o_t = \tau(a_t), \quad c_{t+1} = c_t \oplus a_t \oplus o_tat​∼π(⋅∣ct​),ot​=τ(at​),ct+1​=ct​⊕at​⊕ot​

The model samples an action from its context, the tool produces an observation, the context grows by one action-observation pair, and you loop until the model emits a final answer or a stop condition fires.

Chain-of-thought: reasoning moves into the generation stream

January 2022. Wei et al. publish Chain-of-Thought Prompting Elicits Reasoning in Large Language Models. Their few-shot prompts include worked reasoning examples before the test question. That differs from the later zero-shot “let’s think step by step” technique. On GSM8K, the paper reports a large improvement for PaLM-540B when prompted with those intermediate steps.

The experiment changes the prompt without updating the model’s architecture or weights.

Intermediate generated tokens give later tokens more context to work from. ReAct uses that idea alongside external actions. A visible reasoning trace can help debugging, but it is not a guaranteed faithful account of the model’s internal computation.

Tool-using language-model systems also predate ReAct, including WebGPT. This is a selected history of influential ideas, not a claim that the agent loop began in 2022.

ReAct: the loop gets a name

October 2022. Yao et al. publish ReAct: Synergizing Reasoning and Acting in Language Models.

ReAct interleaves Thought tokens with Action tokens (like search("Arthur's Magazine")) and Observation tokens (the tool's response). Prompting or training teaches the model to alternate these steps until it emits a final answer.

  • It works just as prompting, not only with fine-tuning. The format is simple enough that a big model can follow it from a few in-context examples.
  • It makes the loop legible. You can read a ReAct trace and inspect the generated rationale alongside the tool action and observation.
  • It's model-agnostic. The format can be prompted across models, although their ability to follow it varies. The protocol is in the prompt, not the weights.

Toolformer: training the behavior into the weights

February 2023. Schick et al. publish Toolformer: Language Models Can Teach Themselves to Use Tools.

Toolformer builds a self-supervised dataset for tool use. A pretrained LM proposes calls inside text; the system executes them and retains annotations that reduce prediction loss on the following text. The model is then fine-tuned on those annotated examples.

Function calling: the action gets a schema

June 2023. OpenAI ships function calling in the Chat Completions API. The API now accepts a list of function definitions in JSON Schema, and the model can return a structured function_call object alongside (or instead of) the text.

The API exposes the action as named fields, so applications can handle calls without extracting them from free-form prose.

The definitions provide argument schemas, and the response separates the function name and arguments from prose. The June 2023 API still required applications to check conformance. Later strict-output modes added constrained decoding for supported schemas. Other providers also added structured tool interfaces.

Execution, validation, recovery, and stopping remained application responsibilities.

Voyager and Reflexion: memory and self-critique

Spring 2023. Two papers that push on pieces of the loop that function calling didn't touch.

Reflexion (Shinn et al., March 2023) adds a verbal self-critique step. After a failed trajectory, the agent writes a short natural-language reflection and stores it as memory for the next attempt. The paper reports improvements on HotpotQA and AlfWorld. The underlying weights stay fixed; the next attempt receives the reflection as additional context.

Voyager (Wang et al., May 2023) takes this further in a Minecraft environment. The agent writes executable code, stores working skills in a library keyed by natural-language description, and retrieves them later when a relevant situation arises. The library lets later attempts reuse working code without retraining the underlying model. A coding agent can similarly store a tested script for later use.

Tree-of-Thoughts, also 2023, pushes on the model-step piece by letting the agent search over multiple reasoning branches before committing. This adds an explicit search procedure around model generation.

2024–25: interfaces and infrastructure

The following releases illustrate different changes to the agent interface: a curated coding environment, screen actions, a shared tool protocol, and new API representations.

SWE-agent (Yang et al., 2024) showed that a general-purpose language model, wrapped in an "agent-computer interface" (a careful curation of shell commands, file views, and edit operations exposed as tools), could solve real GitHub issues. It demonstrated how the agent-computer interface affects software-task performance.

Anthropic Computer Use (October 2024) gave a model a screenshot and a mouse, and asked it to do things. The model can request screenshot-based mouse and keyboard actions, within the runtime’s supported action set and permissions.

MCP (Model Context Protocol, November 2024) took the function-calling idea and cut it loose from any one provider. A single MCP server exposes tools, resources, and prompts, and compatible MCP clients can discover them. Hosts still translate those definitions into the selected model API.

OpenAI Responses API (March 2025) added an item-based API for model responses and tools. The Harmony format published with gpt-oss (August 2025) documented a token-level representation with roles, channels, and recipients. These operate at different layers: API objects versus rendered model input/output.

2025–26: agents that ship

Examples of deployed agent interfaces include:

Coding agents — Claude Code, Cursor's agent mode, Devin, Codex CLI. The agent edits files, runs tests, reads the output, keeps going. The loop interleaves actions and observations; the tools are a curated set of file and shell operations; the memory is a combination of the open editor state, a running scratchpad, and context-management mechanisms such as summaries or delegated subtasks.

Computer-use agents — Anthropic's Computer Use, OpenAI's Operator, various browser-pilot products. The model requests pointer and keyboard actions from screenshots. The runtime must execute those actions and obtain another observation to check their effect.

Retrieval-and-answer agents — the ones living inside Perplexity-style products, enterprise search, and most "chat with your docs" deployments. They use retrieval and tool calls to assemble evidence before answering.

Systems using this loop can differ in:

  • Model training for tool selection and coding.
  • The available actions and how their arguments are validated.
  • Tools can use documented interfaces, including MCP and provider APIs.
  • Context management, including compaction (Context Engineering), summaries, and delegated subtasks that reduce how much intermediate output the caller retains.
  • A runtime can add retries, logging, evaluations, and approval gates.

Misconceptions

"An agent requires a new neural architecture." A tool loop can wrap an existing language model. Agent design also includes the runtime, available tools, training, and context policy; the word alone does not identify a particular neural architecture.

"ReAct is obsolete, we have function calling now." Function calling provides structured fields for actions; strict modes can additionally constrain arguments. ReAct remains a useful example of interleaving generated rationale with actions and observations, even when a modern system uses a different prompting or training method.

"Chain-of-thought prompting is the same as a reasoning model." Prompting with intermediate examples and training a model to use extra reasoning compute are different interventions. DeepSeek-R1 documents reinforcement-learning methods; proprietary models expose reasoning controls without necessarily disclosing an equivalent training recipe.

"Agents will replace function calling / prompting / RAG." Agents are the outer loop that those things live inside. A modern coding agent uses retrieval to grab relevant code (RAG), runs tools with structured schemas (function calling), and sometimes even prompts itself with specific personas for sub-tasks.

Additional reading (and watching)

  • Wei, J., et al. (2022). Chain-of-Thought Prompting Elicits Reasoning in Large Language Models. arXiv:2201.11903. Demonstrated few-shot prompting with worked intermediate reasoning steps.

  • Yao, S., et al. (2022). ReAct: Synergizing Reasoning and Acting in Language Models. arXiv:2210.03629. Introduced the thought/action/observation loop as an explicit prompting pattern. A useful reference for inspecting tool-use transcripts.

  • Schick, T., et al. (2023). Toolformer: Language Models Can Teach Themselves to Use Tools. arXiv:2302.04761. A self-supervised recipe that filters candidate tool calls by their effect on prediction loss.

  • OpenAI. (2023). Function calling and other API updates. Introduces function definitions and structured call responses in Chat Completions.

  • Shinn, N., et al. (2023). Reflexion: Language Agents with Verbal Reinforcement Learning. arXiv:2303.11366. Studies storing verbal feedback for a later attempt.

  • Wang, G., et al. (2023). Voyager: An Open-Ended Embodied Agent with Large Language Models. arXiv:2305.16291. A Minecraft agent that stores and retrieves executable skills.

  • Yao, S., et al. (2023). Tree of Thoughts: Deliberate Problem Solving with Large Language Models. arXiv:2305.10601. Search-over-thoughts as an upgrade to the model-step of the loop.

  • Yang, J., et al. (2024). SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering. arXiv:2405.15793. Showed that with a well-designed tool surface, a general LLM could solve real GitHub issues. Studies how interface design affects a coding agent’s performance.

  • Anthropic. (2024). Introducing the Model Context Protocol. The announcement of MCP. Cited here as the canonical entry point for the protocol that standardized tool interfaces across providers.

  • Anthropic. (2025). Claude 3.7 Sonnet and Claude Code. February 24 announcement of the Claude Code research preview.
