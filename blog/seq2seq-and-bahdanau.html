Seq2seq, Bahdanau Attention, and Why Recurrence Hit a Wall

How do you translate a sentence from English to French using a neural network?

The input and output may have different lengths and word orders. "I am going to the store" becomes the shorter "Je vais au magasin." In "the black cat" → "le chat noir," the adjective moves after the noun. A translation model has to learn these correspondences without assuming one output token per input token.

In 2014, Cho et al. introduced an RNN encoder-decoder that scored phrase pairs for a statistical translation system. Sutskever et al. demonstrated end-to-end translation with a deep LSTM encoder-decoder on WMT'14 English–French. Both pass information from an encoder to a decoder; the design question here is how much of the source the decoder can access.

The encoder-decoder architecture

You take two RNNs (or LSTMs, in practice). The first one, the encoder, reads the source sentence one token at a time and builds up a hidden state. When it reaches the end of the input, its final hidden state is supposed to represent the "meaning" of the entire source sentence. That single vector is the context.

The second RNN, the decoder, takes that context vector as its initial hidden state and generates the target sentence one token at a time, feeding each predicted token back as input for the next step.

So the information flow looks like: source tokens →\rightarrow→ encoder RNN →\rightarrow→ single fixed-length vector ccc →\rightarrow→ decoder RNN →\rightarrow→ target tokens.

The context vector ccc has a fixed dimension regardless of source length. This creates a bottleneck: the final encoder state must preserve everything the decoder will need, even for a long input.

The effect of that bottleneck differed across systems. Cho et al. observed sharply degrading performance on longer sources in their basic RNN encoder-decoder; Bahdanau et al. saw the same pattern in their RNNencdec baseline. Sutskever et al. reported that their deep LSTM with reversed source sentences "did not have difficulty on long sentences." Attention offered a way to access source positions directly instead of relying on one final state.

Bahdanau attention: learning to align

In 2015, Bahdanau, Cho, and Bengio proposed a mechanism they called "attention." The core insight was to let the decoder, at each generation step, compute a weighted combination over all of the encoder's hidden states, rather than relying only on the final one.

Bahdanau's encoder is bidirectional. Each annotation hjh_jhj​ concatenates forward and backward recurrent states, giving source position jjj context from both directions. The decoder attends over these annotations.

The encoder computes the annotations once for the source sequence. At decoder step ttt, using hidden state st−1s_{t-1}st−1​, we compute:

Alignment scores (how relevant is each source position to this decoder step):

etj=va⊤tanh⁡(Wast−1+Uahj)e_{tj} = v_a^\top \tanh(W_a s_{t-1} + U_a h_j)etj​=va⊤​tanh(Wa​st−1​+Ua​hj​)

where WaW_aWa​, UaU_aUa​, and vav_ava​ are learned parameters. This is called "additive" attention because we're adding transformed versions of the decoder state and encoder state, then passing through a tanh nonlinearity.

Attention weights (normalize scores into a distribution):

αtj=exp⁡(etj)∑k=1Txexp⁡(etk)\alpha_{tj} = \frac{\exp(e_{tj})}{\sum_{k=1}^{T_x} \exp(e_{tk})}αtj​=∑k=1Tx​​exp(etk​)exp(etj​)​

That's just a softmax over the source positions. Each αtj\alpha_{tj}αtj​ tells us how much the decoder should "attend to" source position jjj when generating target token ttt.

ct=∑j=1Txαtjhjc_t = \sum_{j=1}^{T_x} \alpha_{tj} h_jct​=j=1∑Tx​​αtj​hj​

The context vector ctc_tct​ can differ at each decoder step. When generating "chat," attention may concentrate on "cat"; for "noir," it may concentrate on "black." The weights let the decoder combine source information differently for each prediction.

The decoder then uses both ctc_tct​ and st−1s_{t-1}st−1​ to compute the next hidden state and predict the next target token.

A quick word on Luong variants

Luong et al. compared several scoring functions in 2015, including a dot product between the decoder and encoder states.

Dot-product scoring:

etj=st⊤hje_{tj} = s_t^\top h_jetj​=st⊤​hj​

Just the raw dot product between decoder and encoder states. Fast, simple, no extra parameters. But requires the decoder and encoder hidden states to live in the same dimensionality.

General scoring:

etj=st⊤Whje_{tj} = s_t^\top W h_jetj​=st⊤​Whj​

A learned matrix WWW projects the encoder states before the dot product.

Concat scoring (essentially the same as Bahdanau):

etj=v⊤tanh⁡(W[st;hj])e_{tj} = v^\top \tanh(W[s_t; h_j])etj​=v⊤tanh(W[st​;hj​])

Concatenate the two vectors, transform them, and project the result to a scalar. Like Bahdanau's score, this includes a learned nonlinear transformation.

Luong's work helped normalize simpler multiplicative attention forms. Their strongest reported local-attention system actually used the "general" score function with the learned WWW, not raw dot product, but the multiplicative family as a whole proved competitive with additive attention while being faster. Two years later, the Transformer used a scaled dot product, mainly because it maps very efficiently to batched matrix multiplication and the scaling fixes large-dimension softmax saturation. We'll get there in Arc 4.

Why sequential processing hit a wall

Attention gives the decoder access to individual source states, but a recurrent encoder still computes those states in order.

An RNN processes tokens one at a time. To compute h5h_5h5​, you need h4h_4h4​. To compute h4h_4h4​, you need h3h_3h3​. This is an inherently sequential dependency chain. For a sentence with nnn tokens, you need O(n)O(n)O(n) sequential steps through the encoder, and you can't parallelize them.

Dependencies within one sequence

    Starts from h₀

  2. 2. black

    Waits for h1

  3. 3. cat

    Waits for h2

  4. 4. sat

    Waits for h3

  5. 5. on

    Waits for h4

  6. 6. the

    Waits for h5

  7. 7. mat

    Waits for h6

The hidden-state recurrence creates a chain of seven dependent updates.

Autoregressive generation still has dependencies between output tokens.

RNNs can batch matrix multiplications across examples and hidden units. Within a single example, however, hth_tht​ depends on ht−1h_{t-1}ht−1​. Vaswani et al. described this as computation factored "along the symbol positions," which "precludes parallelization within training examples."

Adding hardware can process more examples together, but it does not remove this dependency within an example. The sequence still requires nnn successive state updates.

Misconceptions

"Attention was invented for transformers." Bahdanau attention appeared as a preprint in 2014, three years before the transformer. The 2015 conference paper was about seq2seq translation with RNNs. The 2017 move was to keep this attention idea and drop the recurrence, and we'll cover that in Arc 4.

"Seq2seq models are obsolete and irrelevant." Transformer encoder-decoders retain the sequence-to-sequence abstraction. T5 casts tasks into text-to-text form; BART trains a denoising encoder-decoder. Their cross-attention layers let a decoder access the encoded source.

"Attention fixes the vanishing gradient problem." It adds shorter paths from decoder losses to source states. Gradients within a recurrent encoder still pass through successive state updates and can shrink or grow along that chain.
