Consider three operations: a matrix multiply, a bias addition, and ReLU. If each launches a separate kernel, intermediate results can be written to GPU memory and then read back by the next operation. A fused implementation can keep some of those values close to the arithmetic units instead.

Fusion can save both intermediate memory transfers and kernel-launch overhead. Its benefit depends on the operation’s shape and bottleneck.

Compute needs a supply of bytes

A GPU has several storage levels. HBM holds large tensors; caches retain some recently used data; shared memory and registers support work within a streaming multiprocessor. Registers have finite capacity and access costs, and shared memory is explicitly managed rather than simply another automatic cache.

Arithmetic intensity is the workload's arithmetic operations divided by the bytes transferred across the memory boundary being studied. The roofline compares that intensity with peak compute and bandwidth. A small BF16 matrix-vector product may perform roughly two FLOPs per two-byte weight read; a matrix product over many token positions reuses each weight more.

Softmax needs a global row statistic

For a row of scores sss, stable softmax computes

pi=exp⁡(si−m)∑jexp⁡(sj−m),m=max⁡jsj.p_i=\frac{\exp(s_i-m)}{\sum_j\exp(s_j-m)},\qquad m=\max_j s_j.pi​=∑j​exp(sj​−m)exp(si​−m)​,m=jmax​sj​.

An unfused implementation might read the row for its maximum, read it again to write exponentials, read those exponentials for their sum, then read them again to write normalized output. Ignoring the small reduction vectors, that is four reads and two writes of row-sized arrays.

A fused kernel can read and write the row once if it can retain the needed values on chip. If a row is too large, the algorithm needs tiling or additional passes. Normalizing each tile independently would be wrong because the denominator must include the whole row.

FlashAttention: avoid the full score matrix

Dense attention computes softmax(QK⊤/d)V\mathrm{softmax}(QK^\top/\sqrt d)Vsoftmax(QK⊤/d​)V. Materializing the score matrix for one head needs N2N^2N2 elements. At FP16, N=8192N=8192N=8192 means 128 MiB for that matrix alone.

FlashAttention works on tiles and maintains online softmax statistics. It avoids storing the complete score and probability matrices in HBM. Its auxiliary memory is linear in sequence length, but its total HBM traffic is not universally linear: keys and values can be loaded repeatedly for different query tiles. The original paper analyzes an IO bound proportional to N2d2/MN^2d^2/MN2d2/M over its stated SRAM-capacity regime. FlashAttention paper.

For one query tile, retain a running maximum mmm, normalization sum ℓ\ellℓ, and unnormalized output numerator aaa. When the next score tile has maximum mtm_tmt​, use m′=max⁡(m,mt)m'=\max(m,m_t)m′=max(m,mt​) and rescale the old accumulators by α=exp⁡(m−m′)\alpha=\exp(m-m')α=exp(m−m′):

ℓ′=αℓ+∑jexp⁡(sj−m′),a′=αa+∑jexp⁡(sj−m′)Vj.\ell'=\alpha\ell+\sum_j\exp(s_j-m'),\qquad a'=\alpha a+\sum_j\exp(s_j-m')V_j.ℓ′=αℓ+j∑​exp(sj​−m′),a′=αa+j∑​exp(sj​−m′)Vj​.

After all key tiles, return a/ℓa/\ella/ℓ. The rescaling makes earlier and later tiles share one softmax denominator.

A causal kernel must also apply the correct mask, including partially masked tiles, and safely handle rows with no valid keys. Production implementations add parallel work partitioning, precision choices, and hardware-specific data movement.

The attention operation ends with the weighted value sum; the transformer's learned output projection is a separate operation unless an implementation explicitly combines it. Likewise, an entire gated MLP is not necessarily one kernel. Inspect the actual execution trace before deciding which intermediate tensors were eliminated.
